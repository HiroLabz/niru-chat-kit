# Changelog

## Unreleased

- MUI skin: a long document citation in `SourceList` now wraps inside its chip (full width of the row, as many lines as it needs) instead of being cut at 240 px, so a long file name reads in full on touch and keyboard too. Web citations still truncate on one line with the full title in the hover card.
- Core and MUI skin: slash commands in the composer. Core adds the `SlashCommand` type (`id`, `name`, `description`, `keywords`, `group`, `insert`, `disabled`) and the pure functions `slashQuery(text, caret)` (the `/query` being typed; active only when the slash is the first non-space character of the message and the caret is inside that first token, so "and/or", a URL or a path never opens it), `matchSlashCommands(commands, query)` (names starting with the query, then names containing it, then keyword or description matches, stable within each rank) and `applySlashCommand(text, range, command)` (`{ text, caret }`). `Composer` and `FullChat` take optional `commands`, `onCommand(command)`, `commandsLabel` (default "Commands"), `onManageCommands`, `manageCommandsLabel` (default "Edit commands") and `commandsEmptyText` (default "No matching commands"). Typing `/` opens a list above the box (new `SlashCommandMenu`, driven by the new `useSlashCommands` hook) that filters as you type; ArrowUp, ArrowDown, Home and End move, Enter or Tab pick (Enter does not send while the list has a match), Escape closes it until the text changes, and the mouse hovers and clicks without taking focus from the box. A command with `insert` replaces the `/query` with that template and puts the caret after it; one without it is an action: the token is removed and `onCommand` does the work. Disabled commands are shown but cannot be picked. The input is an ARIA combobox (`aria-expanded`, `aria-controls`, `aria-activedescendant`) over a listbox while commands are passed. Apps that do not pass `commands` see no change. `ComposerProps` now lives in its own file (still exported from the same place).
- Core and MUI skin: voice input that records. `useSpeechInput` takes optional `transcribe(audio: Blob, { mime, durationMs }): Promise<string>`, `microphoneId`, `maxDurationMs` (default 120000) and `disabledReason`; with `transcribe` it records with `MediaRecorder` (mono, echo cancellation, noise suppression and auto gain; MIME type `audio/webm;codecs=opus`, `audio/webm`, `audio/mp4` or `audio/ogg;codecs=opus`, first supported) instead of using the browser's speech recognition, so it works in a Chromium shell with no speech service. The result gains `recorded` (new `useRecordedSpeech` result: `state` idle, asking, recording, transcribing or failed, `elapsedMs`, `level`, `failure`, `detail`, `start`, `stop`, `cancel`) and `disabledReason`. `Composer` and `FullChat` accept `voice` as `true` (as before) or as `ComposerVoiceOptions` (`transcribe`, `microphoneId`, `maxDurationMs`, `disabledReason`, `labels`). The mic shows wherever `getUserMedia` and `MediaRecorder` exist; pressing it records and shows the elapsed time and a level; the mic or Escape stops and appends the text with the usual joining rule; Cancel discards; recording stops by itself at the limit. A failure (permission denied, no microphone, microphone in use, transcription failed with the app's message, nothing heard) is said in plain words in one polite live region, never changes what was typed, and the mic can be pressed again; an empty result is "nothing heard" and adds nothing. With `disabledReason` the mic is shown disabled with that sentence as its tooltip and description, and a recording in progress is discarded. Every track is stopped on stop, cancel, failure and unmount, sending discards a recording, and no audio is kept after `transcribe` settles. New `ComposerVoiceLabels`, `DEFAULT_COMPOSER_VOICE_LABELS`, `TranscribeAudio`, `SpeechFailure`, `RecordedSpeechState`, `RECORDING_MIME_TYPES`. Nothing changes without `transcribe`.
- Core and MUI skin: an activity line on the call. `VoiceSnapshot` gains optional `activity` (a short sentence the app supplies, such as "Searching the web"); `CallStage` and `CallStrip` take `activity` (wins over the snapshot) and `quietAfterMs` (default 8000). While the phase is `thinking` (or `speaking`, if one is still supplied) `CallStage` shows it as a second line under the status inside its one polite live region, and `CallStrip` shows it in place of its status text on the same single line, with an ellipsis and the full text as a tooltip; it goes away on `listening`, never moves focus and does not animate under reduced motion. With no activity, `thinking` keeps its label, and after `quietAfterMs` the line becomes "Still working on it" (new call label `stillWorking`). `createFakeVoiceSession` takes `activity` and `script.setActivity`. New `useCallActivity`. Nothing is drawn without it.
- Core and MUI skin: media under a reply. Core adds the `MediaItem` type (`id`, `kind` image, video or audio, `src` (https, `blob:` or `data:`; the kit never fetches), `status` loading, ready or failed, and optional `alt`, `title`, `mime`, `width`, `height`, `poster`, `durationSeconds`, `filename`). The MUI skin adds the `MessageMedia` block: images in a responsive grid that keeps each picture's shape (`maxColumns`, default 2; `maxHeight`), a skeleton while loading, a failed state with the title and a Retry button when `onRetry` is given, alt text that falls back to the title and then to "Generated image", and a lightbox dialog (focus trapped, Escape closes, arrow keys and Previous / Next between images, Download when `onDownload` is given, the title as its name) unless `onOpen` is given, which is called instead. Video and audio use the native player (`controls`, `preload="metadata"`, `playsInline`, never autoplay, `poster`) with a Download button. Every word is overridable with `labels`; the fade and zoom are off under reduced motion. `Conversation`, `ConversationTurn` and `FullChat` take optional `renderMedia(message)` (drawn under an assistant reply, above the sources, files and turn actions; a reply with media and no text still shows) and `mediaProps` (`onOpen`, `onDownload`, `onRetry`, `labels`, `maxColumns`, `maxHeight`). Nothing changes unless you pass them.
- Core and MUI skin: choose a microphone on a call. `VoiceSnapshot` gains optional `microphones` and `microphoneId`, `VoiceSession` an optional `selectMicrophone(deviceId)`, and new type `VoiceMicrophone`; existing adapters still type-check. `CallStage` and `CallStrip` take optional `microphones`, `microphoneId` and `onSelectMicrophone` (they win over the session). When something can select a microphone, a small "Choose microphone" caret next to the microphone button (and on the minimised strip) opens a menu with the one in use checked (`menuitemradio`), also for a single microphone; with none listed it shows one disabled row "No microphone found". New call labels `chooseMicrophone`, `noMicrophone`, `unnamedMicrophone`. `createFakeVoiceSession` takes `microphones` and `microphoneId` and `script.setMicrophones`. Nothing is drawn without them. The minimise button and the strip's "Open call" button were already there and labelled; the call docs now describe how an app switches between the stage and the strip.
- Core and MUI skin: agent questions are a card in the thread. `QuestionCard` is rebuilt: `question`, `options` (numbered full-width rows, at least 44 px, keys 1 to 9 pick one; a tapped row shows as picked, then the answer sends), `onAnswer`, `onOther` (adds a "Something else" row), `decideAnswer` / `decideLabel` ("Let the agent decide", only when you give a phrase), `answered` (folds into one line, the question and the bold answer), `onChange` (a "Change" link, for you to show only while the agent has not used the answer), `showQuestion`, `pending`, `keyboard`, `labels`. Its old text-box props (`value`, `onChange(text)`, `pending`, `autoFocus`) are gone; that box now lives inside `InterruptPrompt`, which looks and behaves exactly as before. `Composer` takes optional `answering` (`{ question }`: an "Answering: ..." chip and the placeholder "Type your answer"), `answeringLabel` and `answeringPlaceholder`. `Conversation` takes optional `question` (drawn after the last turn; it does not repeat a question the newest reply already ends with), `foldAnswers` and `onChangeAnswer`. `FullChat` now draws a pending question (any interrupt that is not an approval) as that card in the thread instead of the bottom panel, keeps the composer, focuses it when there are no suggested answers, and sends the typed text with `resume`; it takes optional `decideAnswer`, `decideLabel` and `questionLabels`. Approvals are unchanged. Core: `useChatStream` sets `answersQuestion` (`{ question, options? }`) on the user turn that answers a question, so the folded line stays until the conversation is loaded again from history; new `isQuestionInterrupt` and `replyEndsWithQuestion`.
- MUI skin: the kit and its docs fit a phone (320 px and up) in light and dark. `FullChat`'s root takes `min-width: 0` (the wide pills row and composer no longer widen the page). `ChatHistorySidebar` below `collapseBelow` is now a slide-in drawer opened from the "Conversations" button (it used to open in flow above the chat); new `ChatHistoryDrawer`. `Composer` moves its `toggles` into the More menu as checkable items (`role="menuitemcheckbox"`) when the composer is narrower than 460 px, and its action row wraps so Send and Stop stay visible. Suggestion pills (`ComposerPills`, `ChatEmptyState`) scroll sideways in one row with snapping below `sm` and wrap from `sm` up (new `pillRowSx`). `CallStage` takes optional `overlay` (fixed over the whole screen, `100dvh`, safe-area padding); its control row, status line, captions, header and problem screens shrink to fit 320 px; `CallStrip` truncates and hides its expand icon below 360 px. `ChatTurnActions` rows wrap. Defaults on a wide screen are unchanged.
- MUI skin: fixes for `highlightMessageId`. The tint is now an overlay, so it shows over opaque bubbles. `ChatContainer.Root`'s `holdKey` now also stops a late scroll event (from the chat's own first move to the bottom) from resuming follow-bottom, so the chat is not pulled back down when the highlight ends; the person scrolling, sending, or pressing the jump button resumes following. Matching uses `message.serverId` too, so apps should save `serverId ?? id`.
- Core and MUI skin: pin and save. `ChatHistorySidebar` takes optional `onPin(id, pinned)` (Pin / Unpin in the row menu), `pinned` on items (a Pinned group above the date groups; pinned items come first even when `grouped` is off), `saved` (`SavedItem[]`, adds Chats and Saved tabs), `onOpenSaved`, `onUnsave`, `tab` / `onTabChange` (controlled or not) and `highlightId` (the Chats row flashes when it changes); new label keys. New `ConversationHeader` block (title, Pin and Save toggles with `aria-pressed`, `actions` slot) and `FullChat` `header`. `ChatTurnActions` takes optional `onSave(message)` and `isSaved(message)`: a bookmark toggle after Copy on assistant replies. `Conversation` and `FullChat` take `highlightMessageId`: scrolls that turn into view inside the chat and tints it for about 2.5 seconds (a still outline under reduced motion); each turn has `data-message-id`. `ChatContainer.Root` takes optional `holdKey`. Core adds `SavedItem`, `SavedKind`, `splitPinned`, `filterSaved`, `sortSavedNewestFirst`. Nothing changes unless you pass the new props.
- MUI skin: `CallStrip` lines its content up from the left (it was centred by the button inside it) and shows a small round voice-level orb instead of a dot while the call runs; the expand icon sits at the right, before Mute and End.
- MUI skin: the call lives at the bottom of the chat. `Composer` takes optional `onStartCall`, `callLabel` (default "Start a call") and `callDisabled`: a round phone button in the actions row just before Send. `FullChat` forwards them and takes optional `aboveComposer`, a node rendered directly above the composer (or the interrupt card), for example a `CallStrip`. Default unchanged.
- Core and MUI skin: call mode. Core adds the `VoiceSession` contract (states connecting, listening, thinking, speaking, held, ended, failed; join steps; muted; captions; transcript; capabilities for camera and screen share; local and remote video; problems), `useVoiceSession`, a scriptable `createFakeVoiceSession`, `useLocalMedia` / `createLocalMedia` (camera and screen share previews through `getUserMedia` and `getDisplayMedia`, feature-detected, every track stopped on stop, hold, end and unmount), `followLevels`, `createLevels`, `summariseCall`. The MUI skin adds `CallStage` (Header, Status, Captions, Preview, Controls) in a Gemini Live layout, `VoiceLevelPill`, `CallOrb`, `CallControlButton`, `CallStrip`, `CallCard` and the problem screens. Nothing changes unless you use it.
- Core: `retry()` after a failed send no longer adds the question to the transcript a second time; the question already on screen is re-run.
- MUI skin: `FullChat` forwards `voice`, `voiceLang`, `toggles`, `moreActions` and `moreLabel` to its `Composer`. Default unchanged.
- Core and MUI skin: voice input. `useSpeechInput({ lang, onFinal, onInterim })` (browser speech recognition, feature-detected, safe on the server) and `speechErrorMessage`; `Composer` takes an optional `voice` (and `voiceLang`) that adds a mic toggle with a listening indicator and a short message when permission is denied or nothing is heard. The mic is hidden where the browser has no recognition; sending stops it. Default unchanged.
- Core and MUI skin: `ChatHistorySidebar` takes optional `searchable`, `grouped`, `onRename`, `onDelete`, `labels` and `now`: a search box over title and preview, Today / Yesterday / Previous 7 days / Previous 30 days / Older groups by `at`, and a per-row Rename and Delete (delete asks first). Core adds `conversationAgeGroup`, `groupConversationsByAge` and `filterConversations`. Default unchanged.
- Core and MUI skin: `ChatTurnActions` takes an optional `onDelete(message)`; `TurnActions` then shows Delete behind a confirm on user and assistant turns. Nothing shows without it.
- MUI skin: `Composer` takes optional `toggles` (on/off chips with `aria-pressed`) and `moreActions` (shown behind a "More" button), plus `moreLabel`. Default unchanged. The attachment strip moved to its own file.
- MUI skin: `Tool` takes optional `input` and `output` (text as text, anything else as pretty JSON coloured from the tokens, collapsed until the card opens) and `state`, which accepts the prompt-kit states `input-streaming`, `input-available`, `output-available` and `output-error` as aliases of the existing statuses. Nothing new renders without them.
- MUI skin: `Image` takes `base64` or `uint8Array` with a `mediaType` as well as `src`. Object URLs are revoked on change and unmount; a media type that is not `image/*` is refused with the fallback text.
- Package: `llms.txt` and `llms-full.txt` (an index and a reference of every export of both entry points) are published with the package.
- MUI skin: `FullChat` takes an optional `emptyState` node that replaces the greeting before the first message. Default unchanged.
- MUI skin: with `columnMaxWidth`, the composer's column padding no longer loses to the dark-scheme `padding` rule (the composer spanned the full width in dark).
- Core and MUI skin: `ChatTurnActions` takes an optional `renderExtraActions(message)`; its result is drawn in the same row as Copy, Regenerate and the rating, after them, on a settled assistant reply. Default unchanged.
- MUI skin: `FullChat` takes an optional `disabled` that disables the composer and hides the pills. Default unchanged.
- MUI skin: `FullChat` and `Conversation` take an optional `columnMaxWidth` (px) that centres the turns, and for `FullChat` the composer, in a column with a 24 px minimum gutter; the transcript and its scrollbar stay full width. Default unchanged.
- MUI skin: the turn timestamp carries a `data-chat-timestamp` attribute so an app can show it on hover only.
- MUI skin: `Conversation` draws no face on the typing row when `liveAvatar` is `null` (before, `null` fell back to the initial); an absent `liveAvatar` behaves as before.
- MUI skin: `AgentAvatar` and `AVATAR_PRESETS` (24 illustrated preset avatars, ids `hiro-01` to `hiro-24`). Accepts the API avatar shape directly; unknown ids, missing avatars and images without a url fall back to `hiro-01`. Optional `linked` badge.

## 0.1.0

First release as a standalone package.

- Core entry (`@hiro/niru-chat-kit`): SSE parsing, frame-to-turn reducer, steps, follow-ups, branches, approvals and `useChatStream`. No UI library.
- MUI skin (`@hiro/niru-chat-kit/mui`): primitives, blocks, `JSXPreview` and the token provider.
- Built ESM output with type declarations; install straight from GitHub.
